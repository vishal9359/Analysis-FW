2 Log format

Data collection by profile framework can be done in two ways.

Offline data collection in which it collects the data in files and stores in
local disk in predefined log folder hierarchy. Later this is consumed by
analysis framework for offline data analysis.

Another is online data collection where profile framework exports the data
streams to external entities like analysis framework. Analysis framework
consumes the live data and perform system analysis.

This section contains the log format which should be applicable to both kind
of data collection. There is single log format applicable for both the
methods of data collection.

3 Log format

This section contains the log format for all kind of data supported by
Profile and Analysis framework. Profile data will be transferred to remote
node in protobuf format. Both sender and receiver will have proto files.
Proto file is the foundation of gRPC with protobuf. It is language
independent format to be shared by client and server machines. For different
type of data, there will be different proto structures (block, file, memory,
SSD, nvme). Format of proto is divided into generic format and component
specific format.

here is the log format:

<Timestamp> <Hostname> <Component> <Tag> <LogLevel> <Component specific
format>


3.1 Timestamp

Timestamp format is as follows

Day Mon Date HH:MM:SS Year

Example - [Sat Jun 27 14:40:48 2026]


3.2 Hostname

Hostname is the name of the SUT machine from where this data is collected. It
is in form of a string.

cat /etc/hostname


3.3 Component

Component is integer value for each defined component

Component                     Integer

Linux Block layer             1
Linux NVMe layer              2
Linux syscall layer           3
Linux filesystem layer        4
Linux memory layer            5
SSD                           6
TBD | Others                  TBD


3.4 Tag

Tag is used to tag the profile data(string) with user-defined tags. It is passed to
the profile framework through API calls (or as boot-up parameter). User can
associate any tag before data collection. It can be used to differentiate
between various runs. Once tags are set, new profile data from here-on will
be marked with current tag.


3.5 Log level

Log Level    Integer Value    Uses

ERROR        1    Profile framework data collection failed, Useful for UVP to
                  report any errors, fatal conditions

WARN         2    Useful for UVP control path data collection to report warnings,
                  kernel traces

INFO         3    Profile framework default logs, UVP default logs

DEBUG        4    Detailed logs, it may be useful for UVP control path data
                  collection
