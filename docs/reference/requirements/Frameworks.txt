# 1 Introduction

We want to develop a framework called "System Analysis Framework" which can be used any type of SSD overheads while running various AI use-cases on GPU based desktop systems (like DGX spark and DGX workstation). This framework must do automatic setup of any type of AI workloads, configure the system (and SSD), execute AI use-cases, do profiling , do data collection and do processing or analysis, show the data on UI.
Here analysis means analysis on the data collected to identify SSD/Host overheads and define overall system behavior (Host and SSD domains)

This kind of framework is required for three projects, 
one is "On Device AI" , second is "Tracevision", third is "UVP Control"

In on device AI there can be n numer of AI use-cases on GPU based will be running, similary "Tracevision" and "UVP Control" side we would be having something to profiling which is not clear now but we will get clarity later.

Since all three need similar kind of System Analysis Framework so we think lets develop single common or generic framework which can be used any storage related usecase.

This System Analysis Framework is responsible to execute various use-cases (AI use-cases, enterprise storage) on AI based platforms or enterprise servers and do overall system analysis in host and SSD domains including identifying host system behavior, IO patterns, SSD behavior and system debugging. This document captures the requirements for system analysis framework. Requirements are arranged priority-wise where P1 items will be executed as a first release.

# 2 Requirements

System analysis framework is divided into multiple sub-frameworks including Use-case run & deployment framework, Profile framework, Analysis framework, Tool deployment and UVP control framework. This document covers the requirements of Use-case run & deployment framework and Profile framework. Post deployment and profile framework is defined, analysis framework will be taken care.
